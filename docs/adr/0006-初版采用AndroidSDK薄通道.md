# ADR 0006：初版采用 Android SDK 薄通道

**状态**：已接受为初版实现选择（2026-11-13）；**数据源 D1 的最终验收尚未全部完成**。
**关联**：[ADR 0003](0003-AndroidSDK检索组件静态探针.md) §8–9、
[ADR 0004](0004-百度Flutter插件评估与原生薄通道.md)、方案 v0.2 §4.2 / §10。

## 背景与证据

原计划等待 SDK 的字段、性能与 Flutter 共存证据后再选数据源。2026-11-13，修正探针的
Application Context、成功枚举和鉴权等待问题后，主代理统一在真机执行了一轮六项串行检索：

| OD | 公交 | 步行 |
|---|---|---|
| metro_direct | 903 ms，5 条方案 | 538 ms，1 条方案 |
| bus_transfer | 1121 ms，5 条方案 | 480 ms，1 条方案 |
| walk_short | 410 ms，RESULT_NOT_FOUND | 234 ms，1 条方案 |

六项均发起成功；五项返回 `NO_ERROR`，短途公交明确无结果。两份公交共 15 个乘车段，
线路、方向、上下车站、站数及首末班字段无缺失。真实例子已确认方向不是下车站：
轨道交通 1 号线「张洼方向」与下车站「合肥火车站」不同。

Flutter + Search SDK 的完整 debug / release APK 均已构建成功：debug 为 191,122,871 B，
本轮 release 首构建为 57,384,095 B（约 57.4 MB，十进制），均无 `libc++_shared.so` 合并冲突。
**debug 体积不能与旧 release 约 48 MB 直接比较**；两个 release 也未做 ABI/配置和新增依赖的
严格匹配，只作不同轮次参考，不能把差额全部算成 SDK 增量。

正式 Flutter 薄通道另完成一次公共地标 smoke：`searchPoi → poiDetail → transit → walking`
四次串行调用，POI 候选 10 个、详情成功（无导航点）、公交关键乘车字段齐全、步行成功，
结束后 `blocked=false`。入口 `app/tool/live_sdk_smoke.dart` 只在 debug 且显式启用
`RUN_LIVE_BAIDU_SMOKE` 时可运行，正式 main 不引用，不获取实际位置。

用户明确要求由主代理总调度、调用子代理加速开发，并特别要求遵守百度并发限制。
据此，UI、存储、原生通道按可替换接口并行实现；百度联网检索只由主代理串行执行。
这项开发授权不等于原有验收项目自动通过。

## 决策

1. **初版采用 B：Android SDK 本地检索，无自建后端。** 依赖
   `com.baidu.lbsyun:BaiduMapSDK_Search:9.0.0`，不引入 MapView、导航 SDK 或百度定位 SDK。
   导航继续通过百度 URI 调起外部客户端。
2. **路线使用自建薄平台通道。** `seniornav/baidu` 返回现有 Web API 形状，保留方向、首末班和
   `steps` 分组；Dart 复用已有解析、选路与摘要规则，不另写一套文案，不用下车站补方向。
   未识别车辆类型保留 `unknown`：本轮除 type 0/1 外还出现 type 10 专线。
3. **POI 也使用同一 9.0.0 Search SDK 的薄通道。** 这调整了 ADR 0004 D2
   「B 路可采用官方 Flutter 插件 POI 部分」的有条件建议。官方插件绑定的原生版本是 8.2.0；
   初版共用已接入的 9.0.0 初始化、AK 与并发锁，避免两种版本和初始化路径混用。
   搜索与富详情保留 `naviLocation`，家属仍须打开地图核对并明确确认入口后才保存。
   **POI 的完整真机录入与入口精度不因路线探针通过而自动验收**。
4. **UI 与存储不绑定百度实现。** `RouteService`、`PoiService`、`NavigationService`、
   `PlaceRepository` 为替换边界；若 SDK 后续不能满足要求，可切换到 A 路无状态代理，
   不重写五按钮首页、本地地点库或摘要规则。
5. **路线无结果与检索失败分开。** `RESULT_NOT_FOUND` 已在短途公交观察到，适配为空路线并保留
   `sdkError`；`ST_EN_TOO_NEAR` 同样按无路线处理，但本轮未实际观察到该枚举。
   鉴权、网络、配额与结构错误不能当成「没有公交方案」，且始终保留打开百度地图的出路。

## 并发与隐私约束

- 个人认证路线服务上限为 3 并发；初版采用更严格的**同一时刻最多 1 项**。
  POI 与路线共享同一个 Dart 操作锁和原生进程级 gate；公交、步行、按需少换乘补查按序等待。
  没有自动重试或循环重启，退出页面也不会释放未完成的 SDK 请求。
- SDK 初始化必须在显式同意说明后进行，等待初始化完成与鉴权状态 0 才能检索。
  Application Context、每请求独立 search 对象和 token 避免生命周期/迟到回调串单。
- 30 秒等待超时返回 `SESSION_BLOCKED`，Dart 停止本会话的新查询，原生槽保留至真实回调。
  SDK 网络超时/网络错误及发起 false 保守阻断，不能把客户端超时视为服务器已释放槽位。
- 部分查询失败时保留此前已完成的路线；阻断状态仍然有效，不能为了展示降级结果而吞掉锁状态。
- Android-端 AK 仅从环境或 Gradle 参数注入 manifest；服务端 AK/SK 不进客户端。
  不打印 SDK 鉴权 message、私人坐标和地址，不落库路线或当前位置。
- 定位为一次前台位置，WGS84 转 BD-09 后查询；主 manifest 无后台定位权限，
  `allowBackup=false` 防止地点数据库被系统云备份。最终安装包权限另由产物审计核对。

## 验证状态与未关闭项目

| 项目 | 当前结论 |
|---|---|
| 原生 gate | 8 项纯 JVM 断言通过，覆盖互斥、超时不释放、false/迟到/重复回调 |
| Dart 防线 | 全量 flutter analyze 零问题、Flutter 测试 108 项通过；含隐私拒绝零调用、路线/POI 共锁、阻断不继续、保留已完成结果、公交使用当前位置 |
| Flutter + SDK 打包 | 完整 debug / release APK 成功，无需添加 `pickFirst` |
| 字段 | 两个 OD 的 15 乘车段关键字段齐全；不能外推到所有线路/城市 |
| 点击至摘要 p95 ≤ 3 秒 | **未完成**；六次请求耗时不含初始化、定位和渲染，样本量也不足 |
| 同段备选分组 | **未完成**；本轮所有内组长度均为 1，没有多备选组样本 |
| 站数与经过站列表关系 | **未完成**；`stop_num` 为正，但 dump 未带经过站数组 |
| 同配置 APK 增量 | **未完成**；不能用 debug 与历史 release 相减 |
| POI、入口、完整 UI 真机流程与老人朗读 | 正式薄通道 POI 搜索/详情已通过公共地标 smoke；实际位置、地点保存、入口核对、完整 UI 流程和老人朗读仍须另验 |

因此本 ADR 允许初版继续开发和试用，**不把 D1 最终验收或整个 M0 标为完成**。
后续发现字段缺失、方向错误或持续性能问题时，记录具体样本并重新评估 B/A，禁止以虚构路线掩盖失败。
