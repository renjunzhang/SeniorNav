# M0 客户端密钥与隐私审计

审计日期：2026-11-12　审计人：开发机本地静态检查（无真机）

结论先说：**服务端 AK/SK 没有进入任何安装包，也没有进入 Git。** 但磁盘上现存的
`app-debug.apk` 是**探针包**，内含真实家庭坐标与 POI UID，不可分发。

## 1. 注入链路：服务端密钥根本没有通往客户端的路

全仓库只有一处读取构建期环境变量：

| 位置 | 读取的变量 | 内容 |
|---|---|---|
| [app/lib/probe_places.dart:18](../../app/lib/probe_places.dart) | `PROBE_PLACES_JSON` | 真实地点（坐标/UID/名称） |

`BAIDU_MAP_AK` / `BAIDU_MAP_SK` 只被两个 **Python 工具**通过 `os.environ` 读取：

- [tools/baidu_place.py:24](../../tools/baidu_place.py)
- [tools/baidu_direction.py:30](../../tools/baidu_direction.py)

它们跑在开发机上，不参与 Flutter 构建。Gradle 侧也没有任何注入：
`app/android/app/build.gradle.kts` 里没有 `buildConfigField`、`resValue`、
`manifestPlaceholders`，`gradle.properties` 与 `local.properties` 里没有密钥，
IDE 运行配置里没有附加 `--dart-define`。

也就是说，服务端密钥与 APK 之间**不存在链路**，不是「链路存在但被挡住了」。

## 2. 产物审计（不只看 Git）

工具：[tools/scan_apk_secrets.py](../../tools/scan_apk_secrets.py)。
逐个 zip 条目解压后做字节匹配，分块 8MB、块间重叠 `maxlen-1`，避免漏掉跨块命中。
**只输出命中位置与计数，永不回显密钥或坐标本身**，因此输出可直接贴进文档。

## 4. 需要知道的两个风险

**探针包不可分发。** `app/build/` 已 gitignore，不会入库；但 `app-debug.apk`
里是真实家庭坐标与 UID，反编译 `kernel_blob.bin` 即可读出。给老人装机只能用这个
包（否则目的地是虚构示例点），**不要把它发到群里、网盘或 issue 附件**。

**release 目前用调试签名。** `build.gradle.kts` 的 release 块写着
`signingConfig = signingConfigs.getByName("debug")`（Flutter 模板遗留）。
好处是现在 debug 与 release 的 SHA1 相同，百度 AK 绑一个就够；
一旦将来换成正式 release keystore，**SHA1 会变，已申请的 Android-端 AK 会立刻失效**，
必须同步去百度控制台更新。

## 5. 加入百度 Android SDK 后必须重跑

现在「客户端不含任何百度密钥」这个结论，在引入 Android SDK 后会**变成不成立**：
Android-端 AK 按官方要求写进 `AndroidManifest.xml` 的
`meta-data com.baidu.lbsapi.API_KEY`，那是明文、可反编译的。

这不算泄露——Android-端 AK 的设计就是公开的，它靠**包名 + SHA1 绑定**来防盗用，
与服务端 AK/SK 的威胁模型完全不同。但要在审计里把两者分开记：

- 服务端 AK/SK：**任何情况下都不得进客户端**（本次结论：干净）。
- Android-端 AK：可以进 manifest，但**不得复用到服务端调用**，且 SK 永远不进客户端。

重跑命令：

```bash
python3 tools/scan_apk_secrets.py app/build/app/outputs/flutter-apk/app-release.apk
python3 tools/scan_apk_secrets.py tools/sdk-probe/probe/build/outputs/apk/debug/probe-debug.apk
```

## 6. 申请 Android-端 AK 需要的两项标识

百度控制台的 Android SDK 类型应用要填**包名 + 签名 SHA1**，两者都已从实际产物提取：

| 项 | 值 |
|---|---|
| applicationId | `com.seniornav.seniornav` |
| 调试签名 SHA-1 | `CD:11:33:84:63:A3:60:58:9E:9A:B6:46:8E:8D:8B:87:40:E6:B6:00` |

提取命令（`keytool -printcert -jarfile` 对只有 v2/v3 签名的 APK 会失败，必须用 `apksigner`）：

```bash
BT=$ANDROID_HOME/build-tools/36.0.0
$BT/aapt2 dump badging app/build/app/outputs/flutter-apk/app-debug.apk | head -1
$BT/apksigner verify --print-certs app/build/app/outputs/flutter-apk/app-debug.apk
```

主 App 与 SDK 探针**默认同包名、同一张调试证书**（探针 APK 实测 SHA-1 与上表逐字相同），
所以一个 Android-端 AK 两处通用；代价是两个包不能同时装在一台手机上。
详见 `tools/sdk-probe/README.md`。

这两项标识本身不是秘密（包名与证书指纹在任何已安装 APK 里都能读到），
可以入库；**AK 与 SK 不行**，口径见 §5。

## 7. 注入 Android-端 AK 后的重跑结果（2026-11-12）

§5 要求的重跑已执行。**证据级别：构建产物级静态审计。检索一次都没发起，
延迟、字段完整性、鉴权是否真的通过，全部仍待真机。**

AK 交付方式：写入 `.env.local`（权限 600、被 `.gitignore` 的 `.env.*` 忽略、未被 Git 跟踪），
构建时 `set -a && . ./.env.local && set +a` 注入进程环境，
由 `probe/build.gradle.kts` 的 `manifestPlaceholders["baiduAk"]` 读取。
**不用 `-PbaiduAk`**，避免密钥出现在命令行与进程列表里。

**这个 APK 不可分发。** Android-端 AK 明文在 manifest 里（§5 的口径：这是设计，
靠包名 + SHA1 防盗用，不算泄露），但包一旦外流，别人就能拿去消耗本账号配额。
不要上传网盘、不要贴 issue、不要发给他人装机。
